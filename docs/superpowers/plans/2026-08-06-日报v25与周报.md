# 日报 v2.5 + 周报 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 superpowers:executing-plans 按任务实施。步骤使用 `- [ ]` 跟踪。

**Goal:** 按《日报功能设计方案.md》把现有 v2 软件升级为：员工/店长双角色、两段式日报（前台录入+店长对账）、对账桥、状态流转、两版输出，并新增周报模块。

**Architecture:** 在现有 React 19 + TS + Tailwind + shadcn/ui 单页应用内扩展。数据模型扩展 Report 状态与对账字段；计算逻辑集中在 src/lib/calc.js；角色与状态流转在 App.tsx；录入页按角色分两区；导入复用 src/lib/importers.js 并新增经营报表解析；周报为独立页面，复用导入与汇总逻辑。

**Tech Stack:** React 19、TypeScript、Tailwind CSS、shadcn/ui、lucide-react、vite-node（测试）、PyInstaller（打包）。

## Global Constraints

- 界面风格必须遵守 `设计规范.md`：浅灰底白卡片、等宽数字 `.nums`、`money()`/`signedRate()`、固定 PageHeader→MetricCard→SectionCard 结构、只用现有 ui 组件、图标只用 lucide-react、不新增前端依赖。
- 文案中文、简洁、动词开头；破坏性操作二次确认；操作结果 sonner toast。
- 角色：员工模式看不到店长区/银行实收/对账差异/股东版；店长模式需密码。
- 状态流：draft → submitted → reviewing → finalized → sent，锁定规则见任务 3。
- 对账公式：应到账=营业额+储值充值−储值消费；实际到账=现金收款+农商卡到账−现金存入；差异=实际到账−应到账；容差默认 3 元。
- 团购核销（美团/抖音单数与金额）一律手填，不做自动导入。
- 经营报表仅店长导入；日报只依赖经营报表，会员等报表归周报。
- 不新增 npm 依赖；测试用现有 vite-node。

```js
import { test } from "node:test";
import assert from "node:assert/strict";
import { reconcileMetrics } from "./calc";

test("应到账=营业额+储值充值-储值消费；实际到账=现金+银行-存现；差异三档", () => {
  const report = {
    revenue: { table: 728.55, product: 722.9, coach: 785.21, other: 0 },
    quickRevenue: "",
    member: { rechargeAmount: 1000, consumeAmount: 484.35 },
    cashReceived: 2754,
    reconciliation: { bankReceived: 0, cashDeposit: 0, diffReason: "", diffStatus: "" },
  };
  const m = reconcileMetrics(report, { reconcileTolerance: 3 });
  assert.equal(m.expectedRevenue, 2752.31);
  assert.equal(m.actualReceived, 2754);
  assert.equal(m.diff, 1.69);
  assert.equal(m.tier, "normal");
});
```
